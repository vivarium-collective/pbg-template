# pbg-template

A standalone GitHub template for **process-bigraph research workspaces**.

## Two ways to use this

### Option A: GitHub "Use this template"
Click **Use this template** on github.com/vivarium-collective/pbg-template, then in your new repo:

    bash template-init.sh

The script prompts for the workspace name and other parameters, then renders
the `.j2` files into their final form. No plugin required.

### Option B: via the `pbg-superpowers` plugin
If you have the `pbg-superpowers` Claude Code plugin installed:

    /pbg-workspace my-research-workspace

This clones this template, renders placeholders programmatically, initialises
git + venv, and walks the canonical workspace-bootstrap PR flow.

Either path produces the same workspace structure.

## What you get

- `workspace.yaml` — canonical state file (validated against `.pbg/schemas/workspace.schema.json`)
- `models/` — git-submodule home for individual research models
- `datasets/`, `references/` — shared resources, claim ↔ paper mappings
- `reports/index.html` — interactive workspace dashboard (regenerated by `/pbg-report`)
- `scripts/lint-workspace.py` — validates `workspace.yaml` + cross-references
- A canonical PR flow driven by the `pbg-superpowers` skills

## Layout

After `template-init.sh` (or `/pbg-workspace`), you'll have a working tree like:

    my-research-workspace/
    ├── workspace.yaml
    ├── pyproject.toml
    ├── README.md
    ├── docs/
    ├── datasets/
    ├── references/
    ├── models/
    ├── experiments/
    ├── reports/
    ├── scripts/
    └── .pbg/schemas/

## Schema versioning

The schemas in `.pbg/schemas/` are pinned at template-creation time. The
`pbg-superpowers` plugin ships authoritative schemas in its package; running
`/pbg-workspace` overwrites these with the plugin's current version. Direct
GitHub-template users get whatever was last synced into the template repo.
